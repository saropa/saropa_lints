# Fix: Publish Blocker — Core Dart Lint Name Collisions (16.0.0-beta.1)

Three `saropa_lints` rule names collided with real core Dart analyzer lint
names, tripping the publish audit's Check 8 collision gate and blocking the
16.0.0-beta.1 release. All three were renamed with the project's established
`_extended` suffix convention.

## Finish Report (2026-09-04)

### Root cause

`avoid_dynamic_calls`, `avoid_equals_and_hash_code_on_mutable_classes`, and
`avoid_implementing_value_types` — three of the 19 new tier-1 quick-win rules
added earlier in the same beta cycle — were never checked against
`CORE_DART_LINT_NAMES` (`scripts/modules/_tier_integrity.py`) before landing.
All three are real core Dart/Flutter analyzer lint names. The collision gate
(`test/integrity/core_lint_collision_test.dart`, and the equivalent Python
check in `_tier_integrity.py`) correctly failed the publish audit's Step 1.

This is the same failure mode documented in
`plans/history/2026.09/2026.09.03/fix_core_lint_name_collisions.md` one day
earlier (`avoid_null_checks_in_equality_operators`,
`prefer_initializing_formals`) — the collision gate catches new rules
individually as they're added, but nothing currently prevents a *new* rule
proposal from reusing a core lint name before implementation.

### Fix

All three renamed with the `_extended` suffix, the project's established
collision-rename convention:

| Old name | New name |
|----------|----------|
| `avoid_dynamic_calls` | `avoid_dynamic_calls_extended` |
| `avoid_equals_and_hash_code_on_mutable_classes` | `avoid_equals_and_hash_code_on_mutable_classes_extended` |
| `avoid_implementing_value_types` | `avoid_implementing_value_types_extended` |
