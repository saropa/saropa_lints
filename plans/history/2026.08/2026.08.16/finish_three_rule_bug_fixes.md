# Three Rule Bug Fixes — require_ignore_comment_plugin_prefix, avoid_high_cyclomatic_complexity, avoid_large_objects_in_state

Three false-negative/false-positive bugs fixed across the rule engine. All three were discovered during a downstream lint-audit session against `d:\src\contacts` and filed as `bugs/*.md` reports.

## Finish Report (2026-08-16)

### require_ignore_comment_plugin_prefix — false negative on prefixed-but-misspelled names

**Defect:** `_hasBareRuleName()` skipped any ignore-comment name starting with `saropa_lints/` without validating the suffix against the rule registry. A prefixed name with a typo (e.g. `saropa_lints/duplicate_ignore` instead of the real `saropa_lints/duplicate_ignore_comment`) silently passed validation and the suppression did nothing.

**Fix:** Added `_firstUnknownPrefixedSuffix()` to detect unknown suffixes and `_buildUnknownPrefixedCode()` to generate a dynamic diagnostic with a "did you mean?" suggestion when a close match exists (Levenshtein distance ≤ 5 via `_editDistance()`). `_checkPrecedingComments()` now runs both checks independently — bare names get the existing "add prefix" diagnostic, unknown-prefixed names get the new diagnostic with the closest registered rule name suggested. The existing quick fix (`RequireIgnoreCommentPluginPrefixFix`) already safely returns no insertions for already-prefixed names, so no fix-side changes were needed.

**Files:** `lib/src/rules/stylistic/formatting_rules.dart`, `example/lib/formatting/require_ignore_comment_plugin_prefix_fixture.dart` (5 new BAD cases).

### avoid_high_cyclomatic_complexity — false positive on flat switch dispatch tables

**Defect:** `_ComplexityCounter.visitSwitchPatternCase` added +1 per case unconditionally. A 40-case enum→string lookup function crossed the threshold=15 purely from case count, despite having zero logical branching — same cognitive load as a `Map<Enum, String>` literal.

**Fix:** Added `visitSwitchStatement` override that pre-classifies each switch via `_isFlatDispatchTable()`: every `SwitchMember` must have exactly one statement, and that statement must be trivial (no nested `if`/`for`/`while`/`switch`, no ternary, no `&&`/`||`/`??`). Trivial-statement detection uses `_HasBranchingVisitor`, a small `RecursiveAstVisitor` that flags branching nodes. Flat switches count as +1 total; `visitSwitchPatternCase` skips members of flat switches via a `_flatSwitches` identity set. Follows the same exclusion rationale as the existing `copyWith` carve-out.

**Files:** `lib/src/rules/code_quality/complexity_rules.dart`, `example/lib/complexity/avoid_high_cyclomatic_complexity_fixture.dart` (flat 18-case GOOD, branching 17-case BAD).

### avoid_large_objects_in_state — false positive on replaced-not-accumulated collections

**Defect:** The rule flagged all `List`/`Map`/`Set`/`Uint8List` fields in State classes, including those reassigned wholesale to fresh collections (e.g. recomputed caches derived from widget props) that are bounded by their input, not unbounded accumulators.

**Fix:** Added `_collectMethodBodies()` to concatenate method/constructor body sources (excluding field declarations), `_accumulationPatterns` for mutation detection (`.add(`, `.addAll(`, `+=`, subscript-assignment `field[k] = v`), and `_isReplacedNotAccumulated()` to distinguish replaced fields from accumulated ones. A field is suppressed only when at least one reassignment exists and no accumulating mutation is found in any method body.

**Files:** `lib/src/rules/resources/memory_management_rules.dart`, `example/lib/memory_management/avoid_large_objects_in_state_fixture.dart` (3 new GOOD cases, 2 new BAD cases including subscript-growth).

### Test Results

Full test suite: 9295 tests passed, 0 failures. All three rule test files pass (instantiation, metadata, fixture-existence checks).

### Hardening (post-review)

- `_HasBranchingVisitor` now short-circuits via `visitNode` override — stops traversing sibling AST nodes once `hasBranching` is set.
- `_accumulationPatterns` expanded with `.insert(`, `..insert(`, `.insertAll(`, `..insertAll(` to cover List insertion patterns.
- `_isReplacedNotAccumulated` documented with a limitation note: operates on raw source text, not AST, so field names inside string literals or comments in method bodies could cause false matches.
- `require_ignore_comment_plugin_prefix` diagnostic now includes a "Did you mean 'X'?" suggestion via Levenshtein distance (threshold ≤ 5) when the unknown suffix is close to a registered rule name.

### Review Notes

- The dynamic `LintCode` generated by `_buildUnknownPrefixedCode` shares the rule name `'require_ignore_comment_plugin_prefix'` — intentional for tier/config purposes.
- `_isReplacedNotAccumulated` uses string-matching on raw source text (consistent with the file's existing style) rather than AST-based analysis. Documented limitation; adequate for typical State classes.
- `_editDistance` is O(m × n) but only runs once per diagnostic on short strings (~30 chars), so no performance concern.
